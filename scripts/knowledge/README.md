# ナレッジINDEXとノート検査

対象repoの作業コピーにあるナレッジのヘッダーからINDEXを生成し、変更したノートを検査する処理をまとめる。ノートの形式・参照先・保護対象の規約は [ナレッジのノートとINDEX](../../docs/knowledge-notes.md) が正本で、ここでは実行方法と作用先を説明する。

## 実行

```sh
python3 scripts/knowledge/index.py <作業コピー> [--area <領域>] [--notes-only]
python3 scripts/knowledge/check.py <作業コピー> [<path> ...] [--base <ref>] [--all]
```

`<作業コピー>` は対象repoのrepo直下を指す。DevSpaceからの相対パスでも絶対パスでもよく、worktreeを渡した場合はそのブランチのナレッジだけを読む。固定の親相対パスは仮定しない。

- 入力: `<作業コピー>/docs/knowledge/` のMarkdownと、repo名・ブランチ名・変更ファイルを得るための読取専用のGit問合せ。`check.py` は、削除・移動したファイルがあると作業コピー内の、Gitの無視対象を除く追跡・未追跡の `.md` ファイルもすべて読む。
- 出力: 標準出力へのMarkdown。INDEXファイルは保存しない。追跡ファイル・Git index・作業ツリーは変更しない。
- 環境: Python 3（追加パッケージなし）。DevSpaceのコンテナとネイティブ環境の両方で同じ結果になる。

`index.py` は `docs/knowledge/` が無い作業コピーでは終了コード2で理由を示す。`check.py` は指摘が1件以上あれば終了コード1を返す。保護対象の変更は指摘ではなく、人のマージが必要な変更として一覧に出す。

`index.py` の `--area` はノートだけを絞り、領域文書は残す。

`check.py` の既定の対象は未コミットの変更（staged・未staged・未追跡）で、`--base` を足すとそのrefからの差分も検査する。公開前の確認は `--base origin/<既定ブランチ>` を使う。削除・移動したファイルがあれば、Gitの無視対象を除く作業コピー内の `.md` ファイルをすべて読み、旧パスへの参照を探す。この検査では、ディレクトリへの参照は、その下にファイルが残っていなければ切れたとみなす。入口か領域文書を変更したときと `--all` では、入口の本文リンクと、領域文書が案内表の行からリンクされているかも検査する。入口がないのに領域文書が残っていれば指摘する。パスを明示した場合は、そのファイルを検査し、領域文書か入口を含むときは入口も検査する。指定したファイルがなければ終了コード2で止まる。このとき作業ツリーと `--base` の差分にある削除・移動は扱わず、`--base` は保護対象の判定にだけ使う。保護対象の一覧には、指定したうち実際に変更したファイルだけを出す。パスと `--all` を併せて指定すると、指定したファイルの検査に入口の検査が加わる。ナレッジ文書として扱うのは `docs/knowledge/` 配下の `.md` だけで、`ids` はAssetの作業コピーでは対象のディレクトリがあるかも確かめる。開けないかUTF-8で読めないナレッジ文書は指摘する。削除・移動の検査で読めない `.md` ファイルがあった場合も、旧パスへの参照を確認できないため指摘する。`index.py` は、開けないかUTF-8で読めない文書をINDEXから除き、そのパスを標準エラーに出す。BOM付きのUTF-8は読める。`check.py` は、`--base` のrefを解決できないかHEADとの共通の祖先がない場合と、gitで作業コピーや変更・ファイルの一覧を読めない、または `GIT_DIR`・`GIT_WORK_TREE` が別の作業ツリーやrepoを指す場合と、ディレクトリを読めず検査を続けられない場合に、終了コード2で止まる。読めないディレクトリの中の未追跡ファイルと、リンク先のないシンボリックリンクは、`check.py`・`index.py` とも検出しない。別の環境で作ったworktreeでは、worktreeの名前が `GIT_DIR` と一致するかだけを確かめる。同じ名前のworktreeを持つ別のrepoの取り違えは検出しないため、見出しのrepo名とブランチ名を確認する。`index.py` は、gitの問題があると標準エラーに警告を出し、INDEXは出力する。worktreeを作っていない環境から検査するときは、この2つをコマンドの前置きで指定し、exportしない。

## 変更するとき

ヘッダーのキー・上限・保護対象の一覧は `notes.py` が持つ。規約を変える場合は `docs/knowledge-notes.md` と、子repoの `.github/workflows/auto-merge-docs-tests.yml` の保護対象を併せて更新する。回帰確認は `python3 tests/knowledge.py`。
